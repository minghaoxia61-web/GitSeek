# GitSeek 个人项目说明

## 一句话介绍

GitSeek 是一个评测驱动、证据可追溯的 GitHub 项目与贡献任务推荐系统。它把自然语言需求转成硬约束，通过多路召回、RRF 融合和特征重排生成候选，再使用 GitHub 原始证据核验推荐理由与风险。

## 为什么不只是一个“AI 搜索壳”

- 模型只参与有边界的查询规划，无法放宽许可证、语言和活跃时间等硬约束。
- 模型或向量服务不可用时，规则解析和本地排序仍能完成请求，并明确展示降级状态。
- 推荐质量通过版本化数据集、消融实验、成对偏好和回归门槛验证。
- 仓库内容始终视为不可信数据，不克隆、不执行，也不接受其中的指令。

## 核心链路

```text
自然语言需求
  → 规则/模型约束解析
  → PostgreSQL FTS + 本地语义 + GitHub 多查询召回
  → Reciprocal Rank Fusion
  → 硬过滤与可解释特征重排
  → 仓库工程证据与 Issue 状态核验
  → 用户公开经历与贡献任务匹配
```

## 可量化结果

- 64 个原有后端测试全部通过，并新增 RRF、偏好评测、画像匹配和可观测性测试。
- 100 条相关性查询：Recall@10 87.3%、nDCG@10 89.3%、MRR@10 96.6%。
- 20 组成对偏好：准确率 85.0%。
- nDCG@10 的确定性 Bootstrap 95% 下界为 86.5%。
- 消融实验发现热度权重过高会损害相关性，据此将热度上限从 15 分降到 5 分。

## 工程亮点

- FastAPI、SQLAlchemy、PostgreSQL/Alembic、React、Tauri。
- 并发 GitHub 检索、数据库搜索缓存、仓库向量缓存和可见降级。
- Agent 节点 trace、请求 ID、Server-Timing、P50/P95、错误率和外部服务 token/费用指标。
- GitHub Actions 后端、前端构建与 Playwright 质量门禁。

## 简历描述

独立设计并实现评测驱动的 GitHub 开源项目推荐系统，构建自然语言约束解析、PostgreSQL/语义/GitHub 多路召回、RRF 融合、特征重排和证据核验链路；基于 100 条相关性查询与成对偏好数据，使用 Recall@10、nDCG@10、MRR@10、Bootstrap 置信区间和消融实验优化排序，使 nDCG@10 达到 89.3%；实现公开开发者画像与 Issue 技能匹配、缓存降级、链路指标、版本化迁移和自动化质量门禁。

## 三分钟演示顺序

1. 输入一个包含技术栈、许可证和活跃时间的中文需求。
2. 展示 RRF 召回通道、候选数、耗时和排序解释。
3. 打开仓库档案，查看 README、测试、CI、维护活动等原始证据。
4. 输入 GitHub 用户名，展示公开技能画像与 Issue 适配结果。
5. 打开质量记录，展示消融实验、成对偏好和失败样本。
6. 最后展示 `/api/v1/metrics` 的延迟、错误率和外部调用成本数据。
