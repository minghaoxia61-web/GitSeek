# 运行证据与费用未知状态

日期：2026-10-29。对应优化计划 A8；费用是按配置单价计算的调用估算，不是供应商账单。

## 费用范围与状态

`result_json.billing` 使用 `provider-billing-v1`，范围为本次 worker 尝试的模型与 embedding 调用：

- Issue 解析增强与修复循环共享一个账本；可选代码向量化和向量定位也进入同一账本。
- `estimated_cost_usd` 只有全部调用用量和单价均可确认、没有待完成请求时才为数字；否则是 `null`。
- `known_cost_subtotal_usd` 仅累计可以完整计价的调用，不能当作总费用。
- `unknown_usage_calls`、`unknown_cost_calls`、`pending_calls` 分别指出缺少的证据。
- 没有模型/向量调用时，估算为已知零；这不包含 GitHub、容器、数据库、存储等基础设施费用。
- 供应商失败但回报有效用量时，依然计入估算；网络失败、缺少用量或无效用量不能按免费处理。

每次调用记录阶段、请求哈希、开始/结束时间、耗时、已知 tokens、响应身份/哈希、配置单价、
估算值及错误类型。请求正文和 Authorization 不进入账本；模型回复保留最多 4,000 字符的预览及完整回复哈希。
实际供应商模型或响应 ID 未回报时不补造这些值。

用量未知后停止继续发出模型请求；增强阶段吞掉供应商错误，也不会绕过该门槛触发另一次未知用量请求。
账本的模型 token 预算包含增强调用，按已观测用量在调用边界检查；并非预先精确分词的绝对费用保证。

## 单价配置

以下变量不设置时为未知：

```text
OPENSCOUT_FIXER_INPUT_COST_PER_MILLION
OPENSCOUT_FIXER_OUTPUT_COST_PER_MILLION
OPENSCOUT_FIXER_EMBEDDING_COST_PER_MILLION
```

向量单价未单独设置时，只回退到已有 `OPENSCOUT_EMBEDDING_COST_PER_MILLION` 的正数配置。
本轮不查询或预填任何供应商当前价格。

旧 `.env` 示例曾用 `0` 作未设置占位，不能把这些旧值解释为免费。现在默认将零占位转为未知；
只有确认显式零单价并设置 `OPENSCOUT_FIXER_ZERO_PRICE_CONFIRMED=true` 后，才保留该零单价。
这个配置只是操作者提供的估算依据，不是账单核验。

页面展示“费用未知”或“调用估算”，部分调用已知时另报“已知部分”。很小的正数不会显示成 `$0.0000`。
用量不完整时，输入/输出 token 数也注明只是已知部分。

## 调用前检查点与失败保留

调用开始记录先写本地检查点，再写数据库；写入失败则不派发外部调用。调用返回或抛错后再次记录。
本地/数据库凭证写入失败会阻止后续请求，并作为 `evidence_error` 与模型或工具失败区分。

工具步骤记录命令/路径或补丁哈希、耗时、退出状态、超时以及输出预览/哈希。
本地与 Docker 适配器在 UTF-8 解码前分别计算 stdout/stderr 原始字节 SHA-256；显示日志的格式化输出另有哈希，二者不混用。
超时保留子进程已经捕获的部分输出，标记 `output_complete=false`，`exit_code_kind=timeout_sentinel`；
此时 `124` 是工具的超时约定，不是已经确认的程序退出码。模拟沙箱没有原始字节时，哈希依据明确标为解码文本。
工具动作产生变化后保留当前 diff；Agent 中途失败时，返回带已知 tokens、执行步骤及当前 diff 的部分结果，
由 worker 保存失败原因、用量、验证字段和补丁，而不是把整个任务归零。
`FixerResult.steps` 也会返回实际收集到的步骤，不再只依赖外部回调。

验证状态保持独立：生成了补丁不代表可应用，工作区测试通过不代表独立验收通过，保存了费用记录也不代表修复成功。

## 本地证据目录

可用 `OPENSCOUT_AGENT_EVIDENCE_ROOT` 指定持久目录；默认位于 Agent 工作区根目录的 `_evidence/` 下：

```text
<evidence-root>/<SHA256(run_id)>/<attempt-id>/
    events.jsonl
    receipt.json
    working.diff
    patch.diff
```

- 每次 worker 尝试使用独立 attempt 目录；相同 run ID 的历史尝试不会被覆盖。
- `events.jsonl` 逐事件追加并刷新到磁盘；事件类别与调用种类使用不同字段，避免覆盖。
- `receipt.json` 使用临时文件、刷新及原子替换，保留最新阶段、账本、执行/验收身份和失败原因。
- `working.diff` 是工具动作后捕获的当前 Git 差异，含暂存变化；`patch.diff` 是最终或异常退出时捕获的候选补丁。
  两者可能不同；独立验收只使用最终捕获的 diff，不从工作区复制其他文件。
- 工作区清理不会删除 `_evidence/`；清理失败会写入事件和收据中的警告，不把资源清理成功当成默认事实。
- API 的 `evidence` 给出 run key 和 attempt ID，可据此定位文件，不暴露凭据。

`execution.agent_source` 记录 worker/Agent/沙箱/观测模块与配置、数据模型文件的字节哈希以及可用的 Git commit。
这覆盖未提交的新代码，不把旧 commit 名称单独当作当前代码版本。
实际使用的 Issue 正文另存快照和哈希；后续真实实验仍需在数据集准备时冻结该输入，避免事后编辑泄漏答案。

本地目录的持久性取决于宿主磁盘/卷；临时容器或 serverless 文件系统不能保证跨实例保留，部署时需指定持久位置。
硬杀进程或断电时只能保证已成功写入的检查点；发出请求后尚未拿到用量的记录维持未知，任务租约恢复仍属于阶段 D。
不同尝试的账本不自动合并，账户总账需要结合保留的各 attempt 记录与供应商账单核对。

## 接口、评测与迁移

API 的 `cost_usd` 来自新版 billing 收据；历史行即使曾保存数字零，也不会被视为已确认免费。
评测中只要存在未知费用实例，整体 `avg_cost_usd` 就是 `null`，同时报告已知/未知实例数及已知小计。
数据库指标保存 `cost_known`；未知费用不会作为数值零写入 `cost_usd` 指标。

迁移 `20261029_0012` 允许 `fixer_runs.cost_usd` 为空，升级不改写历史金额。
若仍有未知值，回滚到旧的非空费用字段会明确拒绝；不能为了回滚而自动将未知填成零。
使用新版 worker 前需执行 `python -m alembic upgrade head`，目标为 `20261029_0012`；本轮不自动修改线上数据库。
